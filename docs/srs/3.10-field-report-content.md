## 3.10.1 Submit Field Report

**Function Trigger:**
- **Primary Trigger:** The citizen taps "Báo Cáo Hiện Trường (Ảnh + GPS)" on the Home screen, attaches a photograph and the position, and taps "Gửi báo cáo".
- **Secondary Trigger:** A report queued while offline is sent automatically when the application starts or returns to the foreground with network connectivity.

**Function Description:**
- **Role:** Citizen
- **Purpose:** Lets a citizen report an observation from the field with a photograph, a position and a description, so that officers have ground evidence during verification.
- **Interface:** The Submit Field Report screen includes the following sections:
  - **Page Title:** Displays the title of the field report form.
  - **Photo Capture Button:** Two buttons, "Chụp ảnh" for the camera and "Thư viện" for the gallery; the picked image is resized to at most 1280 pixels at 70% quality.
  - **Photo Preview:** Displays the selected photograph before submission.
  - **Location Field:** Displays the latitude, longitude and accuracy of the captured position, for example "21.84512, 104.08534 (±8 m)".
  - **Get Location Button:** Captures the device position; tapping it again refreshes the position.
  - **Observation Time:** Time at which the citizen observed the event ("Thời điểm bạn thấy sự việc"); it can be chosen within the last 30 days and not in the future.
  - **Description:** Optional description of the observation, at most 2000 characters; required only when no photograph is attached.
  - **Submit Button:** Submits the report to the server or queues it for later submission.
  - **Back Button:** App bar button returning to the previous screen without submitting the report.
  - **Submission Result:** After submission, displays "Đã gửi báo cáo", "Đã lưu trên máy" when the report is queued offline, or "Báo cáo bị từ chối" with the server error, together with the "Báo cáo của tôi" and "Xong" buttons.
- **Screen Layout:** Figure 43. Submit Field Report Screen Layout

**Function Details:**
- **Data:**
  - **Photograph:** Image picked by the citizen, JPEG or PNG, encoded as Base64 and limited to 700 KB.
  - **Position:** Latitude, longitude and accuracy in metres captured from the device.
  - **Observation Time:** Time at which the event was observed; must not be in the future.
  - **Description:** Optional free text of at most 2000 characters; a report needs a photograph or a description.
  - **Client Report Identifier:** Stable identifier generated on the device and submitted with the report so that a retried submission is recognised as the same report.
- **Validation and Business Rules:**
  - **In Normal Cases:**
    - **If the device has network connectivity:** The application uploads the photograph first, receives a photograph identifier, then submits the report referencing that identifier and receives 201 Created.
    - **If a report with the same client report identifier has already been stored:** The server returns 200 OK with the existing report instead of creating a duplicate.
    - **If the device has no network connectivity:** The application stores the report in the local queue with the pending status and shows "Đã lưu trên máy".
    - **If connectivity is restored:** The application retries every queued report with its original client report identifier and updates the local status from the server response.
    - **If the submission succeeds:** The report becomes visible to officers as a community report.
  - **In Abnormal Cases:**
    - **If neither a photograph nor a description is provided:** The application displays "Cần có ảnh hoặc mô tả" and does not submit; the server also returns 400 "A report needs a photo or a description".
    - **If no position could be captured:** The application displays "Hãy bấm "Lấy vị trí" để đính kèm vị trí" and does not submit, because a report without a position cannot be used as evidence.
    - **If the photograph exceeds the size limit:** The application already resizes it when it is picked; if it still exceeds 700 KB the server returns 400 "Image is larger than 700 KB".
    - **If the observation time is in the future:** The date picker does not allow it, and the server returns 400 "observedAt is in the future".
    - **If the photograph upload succeeds but the report submission fails:** The application keeps the photograph identifier in the local queue so that the retry does not upload the image a second time.
    - **If the server rejects the report:** The local record stores the returned error so that the citizen can see why the submission failed.

## 3.10.2 View My Reports

**Function Trigger:**
- **Primary Trigger:** The citizen taps "Báo cáo của tôi" on the Profile screen or on the result screen after a submission.
- **Secondary Trigger:** The citizen checks whether a report queued while offline has reached the server.

**Function Description:**
- **Role:** Citizen
- **Purpose:** Displays the reports a citizen has submitted together with the synchronization status of reports that were created without network connectivity.
- **Interface:** The My Reports screen includes the following sections:
  - **Page Title:** Displays the title of the report list screen.
  - **Report Item:** Displays one report with its observation time and description.
  - **Status Badge:** Shows the status of the report: "Chờ gửi", "Lỗi", "Đã gửi", "Đã xử lý" or "Đã lưu trữ".
  - **Retry Button:** Retries the submission of a report that is still pending or has failed.
  - **Report Detail View:** Displays the error message of a report that could not be sent.
  - **Empty State Message:** Displays "Bạn chưa gửi báo cáo nào." when the citizen has not submitted any report.
- **Screen Layout:** Figure 44. View My Reports Screen Layout

**Function Details:**
- **Data:**
  - **Local Reports:** Reports stored on the device for the signed-in account, most recent first, with their last error.
  - **Server Status:** Status returned by the server for sent reports: submitted, processed or archived.
- **Validation and Business Rules:**
  - **In Normal Cases:**
    - **If the screen is opened:** The application lists the reports stored on the device, sends the pending ones and refreshes the server status of the sent ones.
    - **If the device is offline:** The screen still displays the local reports; pending reports stay "Chờ gửi".
    - **If a queued report is accepted:** The status changes from "Chờ gửi" to "Đã gửi".
  - **In Abnormal Cases:**
    - **If a queued report has failed:** The screen displays the recorded error and offers the "Gửi lại" action.
    - **If the server status cannot be refreshed:** The screen keeps the local records visible.
    - **If the session token has expired:** The application returns the citizen to the Sign In screen without discarding the local queue.

## 3.10.3 View Community Reports

**Function Trigger:**
- **Primary Trigger:** The officer clicks a red community report marker on the WebGIS dashboard map, which opens the "BÁO CÁO CỘNG ĐỒNG" popup with the reporter, description and sent time.
- **Secondary Trigger:** The officer opens the community reports located near an assessment unit from the evidence detail panel.

**Function Description:**
- **Role:** Monitoring Officer, Administrator
- **Purpose:** Allows officers to review citizen observations as supporting evidence during forecast verification.
- **Interface:** The Community Report popup includes the following sections:
  - **Popup Title:** Displays "BÁO CÁO CỘNG ĐỒNG".
  - **Reporter:** Displays the name of the citizen who sent the report.
  - **Report Description:** Displays the description of the observation.
  - **Sent Time:** Displays when the report was sent.
  - **Report Map Marker:** Red marker showing the report position on the map together with the assessment units.
  - **Close Button:** Closes the popup.
- **Screen Layout:** Figure 45. View Community Reports Screen Layout

**Function Details:**
- **Data:**
  - **Community Reports:** Citizen reports with position, observation time, description and photograph reference, returned by GET /api/v1/community-reports.
  - **Photograph:** Image retrieved by its identifier from GET /api/v1/community-reports/photos/{photoId}.
- **Validation and Business Rules:**
  - **In Normal Cases:**
    - **If reports exist:** The map displays one red marker per report.
    - **If the officer clicks a marker:** The popup displays the reporter, the description and the sent time.
  - **In Abnormal Cases:**
    - **If no report exists:** No marker is displayed on the map.
    - **If a photograph cannot be retrieved:** The server returns 404 "Photo not found" and the textual report stays visible.
    - **If the user does not hold the officer or administrator role:** The system returns 403 Forbidden.

## Ghi chú cho nhóm (không đưa vào SRS)
- WebGIS hiện lấy báo cáo cộng đồng từ dữ liệu mẫu (`COMMUNITY_REPORTS` trong `mockEvents.js`), chưa gọi API thật; popup chưa hiện ảnh.
