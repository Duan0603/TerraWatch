## 3.12.1 View System Dashboard

**Function Trigger:**
- **Primary Trigger:** The monitoring officer or administrator signs in on the WebGIS and is taken to the "Trung tâm điều hành" dashboard at the root address.
- **Secondary Trigger:** The officer reopens the WebGIS address with a stored session; officer and administrator accounts land on the dashboard, while citizen accounts are shown the read-only citizen map.

**Function Description:**
- **Role:** Monitoring Officer, Administrator
- **Purpose:** Gives an at-a-glance overview of the hazard situation in the monitored area: how many cells are being watched, how many are waiting for verification and how many are at the extreme or high level. From the same screen the officer can work through the verification queue and inspect the evidence on the map.
- **Interface:** The Dashboard screen includes the following sections:
  - **Navigation Bar:** Displays the "TerraWatch – GeoSentry Platform" brand, the menu items for the role ("Giám sát nguy cơ", "Cảnh báo", "Người nhận" for officers; "Phê duyệt", "Lịch sử cảnh báo", "Quản lý người nhận", "Báo cáo" for administrators), the "Hệ thống trực tuyến" status chip, the "Lịch sử lệnh", "Phát cảnh báo" and "Xuất báo cáo" buttons, the user name with the role and the Sign Out button.
  - **Page Title:** Displays "Trung tâm điều hành" and "Giám sát nguy cơ 24h".
  - **Search Box:** Input "Tìm xã, huyện..." for searching a commune or district.
  - **Monitored Cell Counter:** "Ô theo dõi": number of cells in the queue.
  - **Pending Review Counter:** "Chờ thẩm định": number of cells awaiting a verification decision.
  - **Extreme Level Counter:** "Cực nguy hiểm": number of cells at the extreme hazard level.
  - **High Level Counter:** "Mức cao": number of cells at the high hazard level.
  - **Filter Tabs:** "Tất cả (N)", "Chờ duyệt (N)", "Đã duyệt (N)".
  - **Verification Queue List:** Event cards with the place, hazard level and the approve and reject actions.
  - **Detail Panel:** Map and evidence of the selected cell (described in 3.4 and 3.7).
- **Screen Layout:** Figure 49. View System Dashboard Screen Layout

**Function Details:**
- **Data:**
  - **Hazard Events:** List of cells with place name, hazard level, verification status and geometry, loaded when the dashboard opens; the counters and tabs are computed from this list on the client.
  - **User Profile:** Full name and role of the signed-in account, used for the navigation bar and the role-specific menu.
- **Validation and Business Rules:**
  - **In Normal Cases:**
    - **If the user is signed in with the officer or administrator role:** The system renders the dashboard, selects the first cell of the list and shows its details on the right.
    - **If the officer selects a filter tab:** The queue shows only the matching cells and the counters stay unchanged.
    - **If the officer approves or rejects a cell:** The status of the card and the counters are updated immediately.
    - **If the user is not an administrator:** The "Phát cảnh báo" button is shown dimmed, and clicking it displays "Chỉ tài khoản Admin mới có quyền phát lệnh cảnh báo khẩn cấp."
  - **In Abnormal Cases:**
    - **If no cell matches the selected filter:** The queue displays "Không có sự cố trong bộ lọc này."
    - **If the event list cannot be loaded:** The error is logged and the dashboard renders with empty counters.
    - **If the user is not signed in:** The protected route redirects the user to the Sign In page.
    - **If the session token has expired:** The next request returns 401 Unauthorized; the client clears the session and returns the user to the Sign In page.

## 3.12.2 Record Audit Trail

(Đổi tên mục từ "View Audit Trail" vì chưa có màn xem nhật ký.)

**Function Trigger:**
- **Primary Trigger:** A monitoring officer or administrator records a verification decision on a forecast or a hazard event.
- **Secondary Trigger:** An administrator sends an emergency broadcast.

**Function Description:**
- **Role:** System
- **Purpose:** Keeps a permanent record of every sensitive action, namely verification decisions and emergency broadcasts, so that the origin of any issued warning can be reconstructed afterwards.
- **Interface:** N/A. The audit trail is stored in the database; no viewing screen and no read API are provided in the current release.
- **Screen Layout:** N/A

**Function Details:**
- **Data:**
  - **Event Status History (landslide_event_history):** Event identifier, previous status, new status, user who changed it, note and change time.
  - **Forecast Reviews (forecast_reviews):** Forecast run, reviewer, decision (approved or rejected), reason and review time.
  - **Alert Broadcasts (alert_broadcasts):** Forecast run, assessment unit, sender, title, message, severity, target channel, idempotency key and send time.
- **Validation and Business Rules:**
  - **In Normal Cases:**
    - **If the status of a hazard event changes:** A database trigger inserts a row into the event status history with the old and new status, the verifying user and the officer note.
    - **If a forecast is approved or rejected:** A review row is stored with the reviewer and the reason.
    - **If an emergency broadcast is sent:** A broadcast row is stored with the sender and its content.
    - **If a record is superseded:** The history rows are kept, so that earlier decisions remain traceable.
  - **In Abnormal Cases:**
    - **If the status does not actually change:** No history row is written.
    - **If the acting user account is later deleted:** The history row is kept and its user reference is set to empty.
    - **If a broadcast is repeated with the same idempotency key:** The unique key prevents a second record.

**Table 44. Record Audit Trail**

| # | Audit Record | Stored In | Written When | Main Fields |
|---|---|---|---|---|
| 1 | Event status change | landslide_event_history | Status of a hazard event changes (trigger) | previous_status, new_status, changed_by, note, changed_at |
| 2 | Forecast review | forecast_reviews | A forecast run is approved or rejected | run_id, reviewer_id, decision, reason_notes, reviewed_at |
| 3 | Emergency broadcast | alert_broadcasts | An administrator sends a broadcast | sender_id, title, message, severity, target_channel, idempotency_key |

(Bảng này thay cho bảng cũ có Action Type Filter, Date Range Filter, Actor Filter, Audit Log Table, Pagination Controls. Nếu nhóm muốn giữ mẫu bảng 7 cột thì có thể xóa bảng.)

## 3.12.3 Manage Monitoring Area

**Function Trigger:**
- **Primary Trigger:** The administrator calls GET /api/v1/monitoring-areas, for example from the API documentation page, to review the registered monitoring areas.
- **Secondary Trigger:** The administrator calls POST /api/v1/monitoring-areas to register a new pilot area.

**Function Description:**
- **Role:** Administrator
- **Purpose:** Allows the administrator to list and register the monitoring areas (areas of interest) whose assessment units are included in the forecast cycle.
- **Interface:** N/A. The function is exposed only through the Core API; no WebGIS screen is provided in the current release.
- **Screen Layout:** N/A

**Function Details:**
- **Data:**
  - **Monitoring Area Record:** Area identifier, name, description, MultiPolygon geometry in WGS 84 (EPSG:4326), active flag and creation time.
  - **Create Request:** name, description and geojson (a GeoJSON Polygon or MultiPolygon geometry).
- **Validation and Business Rules:**
  - **In Normal Cases:**
    - **If the list is requested:** The system returns every monitoring area, active or not, ordered by identifier, with its geometry as GeoJSON.
    - **If a new area is submitted:** The system converts the geometry to a MultiPolygon in EPSG:4326, stores it with the active flag set and returns the identifier, name, description, active flag and creation time.
    - **If the area is stored:** A spatial index on the geometry keeps area queries fast.
  - **In Abnormal Cases:**
    - **If the geometry cannot be parsed as GeoJSON:** The system rejects the request with the error "Invalid GeoJSON geometry payload" and no area is created.
    - **If the area name is empty:** The database rejects the record because the name is mandatory, and no area is created.
    - **If an area must be updated, deactivated or reactivated:** This is not supported by the API in the current release and has to be done directly in the database.

## Ghi chú cho nhóm (không đưa vào SRS)
- `/api/v1/monitoring-areas` hiện rơi vào `"/api/v1/**" permitAll()` trong SecurityConfig, nên **ai cũng gọi được, kể cả người chưa đăng nhập**. Đây là lỗ hổng: nên chặn bằng `hasRole("ADMIN")`. Khi đó mới ghi được câu "403 Forbidden for non-administrators" vào SRS.
- Lỗi GeoJSON đang ném RuntimeException, nên có thể trả về 500 thay vì 400.
- Dữ liệu sự cố trên dashboard có thể là dữ liệu mẫu (nút đặt lại dữ liệu mẫu ở chân cột trái), số badge trên menu (1, 3) đang được gán cứng, và các mục menu chưa chuyển trang.
