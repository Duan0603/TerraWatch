# Story 2.4: Community field report API (GPS + photo upload)

Status: review

## Story

As a Citizen using the mobile app,
I want to send a field report with a photo, my GPS position and the time I saw the event, and be able to retry safely,
so that officers get reliable evidence and a flaky connection never creates duplicate or anonymous reports.

**Epic:** Epic 2 (field reports and event inventory) / supports mobile Story 5.2
**Sprint key:** `2-4-community-field-report-api-gps-photo-upload`
**Target service:** Core API, branch `feature/core-field-report-photos`. **Consumer:** mobile Story 5.2 (`feature/mobile-field-reports`).
**Scope note:** this story delivers the API part of epics.md Story 2.4 (authenticated identity, photo/GPS, occurrence time vs report time, provenance, status). Officer label curation, deduplication and negative-sampling policy belong to the data/AI owners (Tú, Duẫn) and are out of scope.

## Acceptance Criteria

1. **AC1 — Identity from the token:** `POST /api/v1/community-reports` requires a valid JWT. The reporter is the authenticated user; a `userId` in the body is ignored. The old fallback to a hard-coded demo user is removed. Without a token → 401.
2. **AC2 — Photo upload:** `POST /api/v1/community-reports/photos` `{imageBase64}` (JPEG or PNG by file signature, valid base64, ≤ 700 KB decoded) stores the picture and returns `{photoId, imageUrl}` where `imageUrl` is `/api/v1/community-reports/photos/{photoId}`. `GET` that URL returns the image bytes with the right content type; unknown id → 404. The URL is public by an unguessable UUID so the WebGIS can show it in an `<img>` (see Dev Notes).
3. **AC3 — Submit, idempotent:** the body carries `clientReportId` (UUID generated by the app), `longitude` (−180..180), `latitude` (−90..90), optional `accuracyM`, `description` (≤ 2000), optional `photoId`, `observedAt` (required, not in the future beyond 5 minutes) and optional `observedUntil` (≥ `observedAt`). First submit → `201` with the report; submitting the same `(user, clientReportId)` again → `200` with the **same** report and no new row. A report needs a photo or a description.
4. **AC4 — Event time vs upload time:** `report_time` stays the server receive time (reported_at); `observed_at`/`observed_until` store when the event was seen; `source` records provenance (`mobile`); `location_accuracy_m` records spatial uncertainty. Existing rows are untouched.
5. **AC5 — Photo ownership:** a `photoId` that does not exist or belongs to another user → 400.
6. **AC6 — My reports:** `GET /api/v1/community-reports/mine` returns the caller's reports newest first (`reportId, clientReportId, status, reportedAt, observedAt, observedUntil, description, imageUrl, latitude, longitude`). Status is the existing enum (`submitted` | `processed` | `archived`).
7. **AC7 — Errors keep their status over real HTTP:** `CommunityReportController` is covered by `AuthExceptionHandler` (a 400/404 must not turn into 401). The existing public `GET /api/v1/community-reports` keeps working and also exposes `observed_at`.
8. **AC8 — Schema:** migration `V7` (both migration folders) adds the columns above to `community_reports`, a unique index on `(user_id, client_report_id)` where `client_report_id` is not null, and table `core_schema.report_photos`.

## Dev Notes

- **Current state (read from code):** `CommunityReportController` has `GET` (public list via `SpatialRepository.listCommunityReports`) and `POST` taking `CommunityReportRequest(userId, longitude, latitude, imageUrl, description)`, falling back to user `33333333-...` when `userId` is null; `SpatialRepository.submitCommunityReport` inserts with `ST_SetSRID(ST_MakePoint(lon, lat), 4326)`. Table: `report_id SERIAL`, `user_id`, `report_time DEFAULT now()`, `location GEOMETRY(Point,4326)`, `image_url`, `description`, `status report_status`. No WebGIS code posts reports (checked), so changing the POST contract is safe.
- **Pattern to reuse:** avatar storage (`UserAvatarService`/`user_avatars`) for base64 + signature check; `JwtAuthenticationFilter` UUID principal; `ErrorStatusOverHttpTest` for the real-HTTP status guard.
- **Lesson learned (Stories 1.5/1.6):** an error from a controller not listed in `AuthExceptionHandler` becomes 401 over real HTTP and signs mobile users out. Add the controller and a real-HTTP test.
- **Gateway:** `/api/v1/community-reports` is already routed (prefix), so `/photos` and `/mine` pass; the default nginx body limit is 1 MB, hence the 700 KB cap (base64 ≈ 933 KB).
- shortcut: photos as base64 text in Postgres (client shrinks to about 1280 px); move to object storage if volume grows.
- shortcut: the photo GET is public by UUID (unguessable) so the WebGIS can render it without a token; revisit if photos become sensitive.
- **Out of scope:** officer review/status changes, deduplication, WebGIS display changes, rate limiting per user.
